# RISC vs CISC

## Overview

RISC and CISC describe two different philosophies for designing a CPU's **Instruction Set Architecture (ISA)**.

The simplest way to remember them:

> **RISC = simpler instructions**  
> **CISC = more complex instructions**

Typical examples:

| Architecture | Type | Server CPU Example |
|---|---|---|
| ARM | RISC | NVIDIA Grace |
| RISC-V | RISC | Various emerging processors |
| x86 | CISC | Intel Xeon, AMD EPYC |

However, modern CPUs have evolved significantly, so **RISC vs CISC alone does not determine CPU performance, power consumption, or efficiency**.

---

# 1. What Is an Instruction?

A CPU cannot directly understand applications such as Linux, Chrome, databases, or AI software.

Software eventually needs to be translated into instructions that the CPU understands.

```text
Application
    ↓
Programming Language
    ↓
Compiler
    ↓
Machine Instructions
    ↓
CPU
```

For example, a CPU may receive instructions such as:

```text
LOAD data
ADD two values
STORE result
```

The complete set of instructions that a CPU understands is called:

> **ISA — Instruction Set Architecture**

Common ISAs include:

- [[x86\|x86]]
- [[ARM\|ARM]]
- [[RISC-V\|RISC-V]]

---

# 2. What Is RISC?

## RISC = Reduced Instruction Set Computer

The main philosophy of RISC is:

> Use relatively simple and regular instructions that the CPU can execute efficiently.

A RISC processor may break one task into several simple instructions.

For example, assume we want to add two values stored in memory.

A simplified RISC approach could be:

```text
LOAD R1, [A]
LOAD R2, [B]
ADD  R3, R1, R2
STORE [C], R3
```

The CPU performs:

```text
Read A
  ↓
Read B
  ↓
Add
  ↓
Store result
```

Each instruction has a relatively specific purpose.

---

# 3. Typical RISC Characteristics

RISC architectures traditionally emphasize:

- Relatively simple instructions
- Regular instruction formats
- Load/store architecture
- Many general-purpose registers
- Efficient instruction decoding
- Efficient CPU pipelining
- High execution efficiency

Common RISC architectures include:

- [[ARM\|ARM]]
- [[RISC-V\|RISC-V]]
- POWER

In modern servers, a major RISC example is:

> [[NVIDIA Grace CPU\|NVIDIA Grace CPU]] → ARM architecture

---

# 4. What Is CISC?

## CISC = Complex Instruction Set Computer

The original CISC philosophy is:

> Allow one instruction to perform more complex operations.

Instead of using several simple instructions, a CISC ISA may provide a more powerful instruction that combines multiple operations.

Conceptually:

```text
ADD memory A to memory B
```

Internally, this may involve:

```text
Read memory
    ↓
Perform calculation
    ↓
Write result
```

The best-known CISC architecture is:

> [[x86\|x86]]

Modern x86 server CPUs include:

- [[Intel Xeon\|Intel Xeon]]
- [[AMD EPYC\|AMD EPYC]]

---

# 5. RISC vs CISC — Simple Comparison

| | RISC | CISC |
|---|---|---|
| Full Name | Reduced Instruction Set Computer | Complex Instruction Set Computer |
| Philosophy | Simpler instructions | More complex instructions |
| Instruction format | Usually more regular | Often more variable |
| Instruction complexity | Lower | Higher |
| Memory operation | Usually explicit load/store | Some instructions directly operate on memory |
| Decode complexity | Traditionally simpler | Traditionally more complex |
| Typical ISA | ARM, RISC-V | x86 |
| Server example | NVIDIA Grace | Intel Xeon, AMD EPYC |

---

# 6. Easy Analogy

Imagine asking someone to make coffee.

## RISC approach

Give several simple commands:

```text
1. Get a cup
2. Add coffee
3. Add water
4. Stir
5. Serve
```

Each command is simple.

---

## CISC approach

Give one more complex command:

```text
Make me a coffee
```

The command is simpler for the person requesting it.

But internally, the person still needs to:

```text
Get cup
   ↓
Add coffee
   ↓
Add water
   ↓
Stir
   ↓
Serve
```

This is similar to how modern CISC processors can internally break complex instructions into smaller operations.

---

# 7. Important: RISC Does Not Mean Fewer Instructions

A common misunderstanding is:

> RISC = fewer instructions

This is not correct.

"Reduced Instruction Set" mainly refers to the **design philosophy and complexity of individual instructions**.

A RISC processor may actually require more instructions to complete the same task.

Example:

### RISC

```text
LOAD
LOAD
ADD
STORE
```

### CISC

Conceptually:

```text
ADD MEMORY
```

So:

> RISC may use more simple instructions.

while:

> CISC may use fewer but more complex instructions.

---

# 8. Why Was RISC Developed?

One important motivation behind RISC was to make CPU instruction execution more regular and predictable.

Consider a simplified CPU pipeline:

```text
Instruction Fetch
      ↓
Decode
      ↓
Execute
      ↓
Memory Access
      ↓
Write Back
```

If instructions are relatively simple and regular, it becomes easier to move many instructions through the pipeline efficiently.

This is related to:

- [[CPU Pipeline\|CPU Pipeline]]
- [[Instruction Decode\|Instruction Decode]]
- [[Out-of-Order Execution\|Out-of-Order Execution]]

---

# 9. Why Does CISC Exist?

CISC also has important advantages.

Historically, memory was:

- Expensive
- Small
- Slow

Having one instruction perform more work could reduce the amount of program code that needed to be stored.

This improves:

> **Code Density**

For example:

```text
Many simple instructions
```

may require more bytes than:

```text
One complex instruction
```

Another major advantage of x86 today is:

> **Backward compatibility**

The x86 software ecosystem has existed for decades.

This gives Intel and AMD processors broad compatibility with:

- Operating systems
- Enterprise software
- Databases
- Server applications
- Legacy applications

---

# 10. Modern CPUs Blur the Difference

This is the most important concept in this chapter.

Do NOT think:

```text
ARM = simple CPU
x86 = complex CPU
```

Modern high-performance ARM and x86 CPUs are both extremely complex processors.

A modern CPU may contain:

- Branch predictors
- Large caches
- Out-of-order execution
- Speculative execution
- Multiple execution units
- Vector processing
- Memory controllers
- High-speed I/O
- Power-management systems

Therefore:

> RISC vs CISC mainly describes the ISA philosophy, not the total complexity of the physical processor.

---

# 11. Modern x86 CPUs Use Micro-Operations

Modern x86 processors usually do not directly execute every complex x86 instruction exactly as it appears.

Instead:

```text
x86 Instruction
      ↓
Instruction Decoder
      ↓
Micro-operations (µops)
      ↓
Execution Engine
```

For example:

```text
Complex x86 instruction
         ↓
     Decode into
         ↓
      µop 1
      µop 2
      µop 3
         ↓
Execution units
```

These smaller internal operations are called:

> **Micro-operations / µops**

Therefore, modern x86 CPUs can be thought of as:

```text
CISC ISA
   ↓
Complex Front End
   ↓
µops
   ↓
RISC-like internal execution
```

This is why the difference between modern RISC and CISC processors is much less clear than it was historically.

---

# 12. Modern RISC CPUs Are Also Complex

Another common misunderstanding is:

> ARM processor = simple processor

This is also incorrect.

Modern ARM server CPUs can contain:

- Advanced branch prediction
- Out-of-order execution
- Large caches
- Multiple execution pipelines
- Vector engines
- High-speed memory controllers
- PCIe controllers
- Advanced power management

For example:

> [[NVIDIA Grace CPU\|NVIDIA Grace CPU]]

uses an ARM-based ISA but is still a sophisticated high-performance server processor.

Therefore:

> **RISC does not mean simple hardware.**

---

# 13. ISA vs Microarchitecture

This is another important distinction.

## ISA

ISA defines:

> What instructions software can use.

Examples:

```text
x86
ARM
RISC-V
```

Think of ISA as:

> **The language that software uses to communicate with the CPU.**

---

## Microarchitecture

Microarchitecture defines:

> How the physical CPU actually implements that ISA.

For example:

```text
ARM ISA
   │
   ├── NVIDIA Grace
   ├── AWS Graviton
   └── AmpereOne
```

All use ARM-family instruction sets, but their internal CPU designs can be very different.

Similarly:

```text
x86 ISA
   │
   ├── Intel Xeon
   └── AMD EPYC
```

Both execute x86 software, but their internal designs are different.

---

# 14. Easy Analogy: ISA vs Microarchitecture

Think about language.

```text
English
   ↓
Person A
Person B
Person C
```

All three understand English.

But each person may have different:

- Speed
- Memory
- Skills
- Efficiency

Similarly:

```text
ARM ISA
   ↓
CPU A
CPU B
CPU C
```

The processors understand the same general instruction language but can have very different performance.

Therefore:

> **ISA defines the language.**

> **Microarchitecture defines the machine executing the language.**

# 18. What Actually Determines CPU Performance?

CPU performance depends on many factors.

## Core Count

More cores allow more parallel workloads.

Related:

- [[CPU Core\|CPU Core]]
- [[CPU Thread\|CPU Thread]]

---

## Clock Frequency

Higher frequency means the CPU can perform more cycles per second.

But:

> Higher frequency does not automatically mean higher total performance.

---

## IPC

IPC means:

> Instructions Per Cycle

A processor capable of completing more useful work per cycle can outperform another CPU even at a lower frequency.

---

## Cache

CPU cache reduces the time required to retrieve frequently used data.

Typical cache hierarchy:

```text
CPU Core
   ↓
L1 Cache
   ↓
L2 Cache
   ↓
L3 Cache
   ↓
DRAM
```

Related:

## Memory Bandwidth

This is especially important for:

# 20. Common Misunderstandings

## Myth 1: ARM Is Always Faster Than x86

False.

Performance depends on:

- CPU design
- Workload
- Core count
- Frequency
- IPC
- Memory
- Software optimization

---

## Myth 2: ARM Always Uses Less Power

False.

ARM architectures can enable highly efficient designs, but actual power consumption depends on implementation.

---

## Myth 3: RISC Means Fewer Instructions

False.

A RISC program may execute more individual instructions.

RISC mainly emphasizes simpler and more regular instructions.

---

## Myth 4: CISC Executes Everything in One Step

False.

Modern CISC processors frequently break complex instructions into internal micro-operations.

---

## Myth 5: RISC CPUs Are Simple

False.

Modern ARM server processors are highly complex.

---

## Myth 6: x86 Is Pure CISC Internally

Not really.

Modern x86 CPUs often translate complex instructions into smaller internal µops.

---

# 24. Modern Reality

The historical distinction between RISC and CISC is still useful for understanding ISA design.

However, modern CPU architectures have converged significantly.

```text
RISC CPU
   │
   └── Advanced modern execution engine

CISC CPU
   │
   └── Decode complex instructions into µops
            ↓
       Advanced modern execution engine
```

Therefore:

> **RISC vs CISC describes ISA design philosophy more than actual CPU complexity.**

And:

> **RISC vs CISC alone cannot tell you which CPU is faster, more efficient, or better for a server.**
